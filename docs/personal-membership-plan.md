# Praxis-RAG 个人会员、支付宝与 Embedding 额度实施方案

交给 DeepSeek v4.1。请基于当前代码实施下列产品规则，遵循仓库 AGENTS.md。本文是设计交付，金额和额度是首发产品配置。实施前检查当前分支是否已有相关实现，复用已有逻辑。

## 1. 套餐与归属

| 个人套餐 | 月卡 | 年卡 | 自有库数 | 每库逻辑文件数 | 每个额度周期的平台文档 Embedding 字符数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Free | 免费 | 免费 | 5 | 10 | 10 万 |
| Plus | ¥19.90 | ¥191.04 | 20 | 100 | 1000 万 |
| Pro | ¥199.9 | ¥575.04 | 不限 | 不限 | 1B |

- 商品目录按上表定价。Plus 年价为月价 × 12 × 0.8。Pro 按指定年价 ¥575.04 下单；其月价调整为 ¥199.90 后，统一按八折计算会得到 ¥1,919.04，Console 只对 Plus 展示“年付八折”。支付宝用人民币，系统内以整数分保存订单金额。
- 1B 表示每个会员月 10 亿个输入字符。年卡分 12 个会员月发放额度，Pro 全年累计可达 120 亿字符，累计计数及账本运算使用至少 64 位整数。额度无现金价值，不结转，首版不自动扣费或出售超额用量。
- 所有者取知识库的 owner_user_id。共享给个人的库数量不限，不占其自有名额。共同维护同一个库的人共享该库所有者账号的文件上限和 Embedding 余额。多个自有库共用一个账号余额。共享者可见该库能否继续上传及限制原因，详细余额和账单仅所有者可看。
- 沿用全库/指定文件的 read、write 授权。先校验操作者权限，再判断所有者权益。Free 可接受共享；Plus、Pro 可分享自有库。到期后保留已有共享，允许撤销，停止新发付费邀请；接收过期会员先前发出的未使用邀请时重新校验邀请资格。
- 保留 admin/vip/user 原角色契约。购买和到期只改会员权益，不改角色。现有手工 vip 保留既有邀请权限，不凭历史角色推定支付记录或赠送永久付费额度。管理员的系统维护权限与其个人消费分开。历史无主库、系统模板继续走管理路径，用量记系统账，不向访问者收费，也不给普通用户创建无主库的入口。

## 2. 文件额度与异步任务

- 同一库中的一份逻辑文档算一个文件。分片、页面、解析图片、版本、任务重试均不单独计数。新增预占，发布成功转为实占，最终失败或取消释放。覆盖原文档沿用原名额。删除已生效后释放；恢复已删除文档需要重新取得名额。
- 建库在 MySQL 同一事务内校验并占用所有者名额。文件受理与预占也在同一事务完成，并沿用已有幂等身份。同一文档的并发新增、覆盖、失败和删除须有明确的预占归属，旧任务不能释放后来者的占位。批量上传按输入顺序逐项裁决，复用已有批次逐文件反馈；已受理项照常运行。
- 会员到期后，已有库、文档、检索和下载继续可用；超限库允许删除、覆盖原文档，等用量降到上限以下才接受新增。已合法受理的文件保留名额，尚未预留的 Embedding 仍按实际调用时的有效额度判定。迁移时用现有已发布文档和未结束任务建立基线，处理重叠，超限存量保留。

## 3. 赠送的 Embedding 怎么用

1. **计量单位。** 首版用“输入字符”方便用户理解并跨模型统一。按实际提交给文档 Embedding 的分片文本计算 Unicode 码点数，空白和重叠切片中重复提交的字符计入。网页显示的是字符，不承诺等同于模型 token 或原 PDF 字数。解析前不根据文件字节数扣额度。
2. **计量范围。** 平台提供的模型处理首次入库、内容变更和用户主动重新向量化时计入；相同内容跳过时计零。查询 Embedding 作为基础检索成本单列，不消耗文档赠额；用完后仍能检索旧文档。BM25、VLM、reranker 和模型配置连通性探测不进这本账。沿用既有模型可用性和检索权限。平台运维主动重建记系统账。
3. **连接归属。** 在服务端标记模型连接由平台供给或由客户自付；模板克隆需传递来源。现有模型连接默认按平台管理来源处理，有可靠依据的自付连接由管理员标记，自付调用不扣平台赠额。普通用户不能借请求字段自己指定免计量。首版无需新增用户自行填写密钥的功能。
4. **预留与结算。** 切分完成后、第一次付费调用前，为整份文档原子预留已知字符数。余额不足时不发起调用，任务显示“所有者的文档向量化额度不足”，复用既有失败状态并提供安全错误类别；避免无意义的自动重试。按成功批次结算，释放未调用或明确失败批次的预留。部分批次已成功，后续 Qdrant 发布失败时仍保留成功批次用量。重新向量化按事前计算或分段预留，余额耗尽时保留旧索引可检索，报告实际已用量。
5. **并发、重试、崩溃。** MySQL 记录账户、发放周期、操作、文档版本、模型及批次身份，用唯一约束确保同一逻辑调用最多向用户扣一次。自动重试复用身份；不同用户主动发起的重算区分操作。超时或进程崩溃导致上游是否成功未知时，保留待核对状态，恢复程序处理；默认 24 小时仍不能证实成功则释放该笔预留，由平台承担不确定成本。重复回调或迟到结果不得追加扣款。预留绑定原周期，跨周期完成不吃新周期赠额。账本可审计，只记录计数和标识，不记录正文、查询或模型密钥。
6. **额度用尽。** 提示下次刷新日期，可等待刷新、Free 升 Plus 或 Plus 升 Pro。Pro 同样有明确的每月 Embedding 上限，Pro 的“无限”仅用于库数和文件数。续购同档只延长期限，不立即再送一份当前月额度。

## 4. 有效期、升级与续费

- 对外按 Asia/Shanghai 显示，内部存 UTC 时刻，周期用左闭右开。月卡从开通时刻起一个日历月，年卡十二个月；按原锚点逐月计算，目标月份没有对应日时取月末，后续月份恢复原锚日。Free 使用上海时区的自然月。每个账户、权益来源和周期只发一次。Free→付费立即启用新的付费周期，停止使用旧 Free 余额；期满回到 Free 时复用本自然月的 Free 账本。
- 同档可续月卡或年卡，顺延现有到期时间和额度周期。已过期重新购买从支付生效时刻起算。Plus→Pro 立即生效，原到期日保持，按原订单月卡/年卡的两档差价乘剩余服务时长占比计算；如有多段续期逐段计算，以分为单位最后四舍五入。当前月额度提高至 Pro 上限，保留本月已用量和预留。未来未开始的已购时段一并升档。首版不售付费期内降档，允许到期后自选。
- 下单前给出准确应付金额、额度变化、生效和到期时间。升级报价绑定权益版本和报价有效期。每个账号一次只允许一笔可支付的权益变更单；旧单先查单、确认关闭或已支付后再建新单。过期单、迟到付款及权益版本冲突进入对账处理，已收款的订单必须可追踪至开通或退款。

## 5. 支付宝和权益到账

- 首版服务于 Web Console，使用支付宝电脑网站支付（alipay.trade.page.pay）。服务端商品目录生成订单号、金额和商品描述，前端只提交套餐、周期或升级意图。订单快照保存价格、账号、套餐、有效期规则和报价，把重复点击映射到同一笔有效订单。
- 浏览器回跳展示订单状态。权益到账依据服务端验签的异步通知或主动查单。核对应用、商户/收款方、商户订单号、币种对应的实付订单金额及交易成功状态，以支付宝交易号、商户订单号和权益事件唯一约束去重。MySQL 事务内确认付款并变更权益，提交后才确认通知成功。超时关单先查支付宝状态，处理回调与查单并发；禁止信任前端“支付成功”。
- 沿用服务默认 loopback、Token 及管理面限制。部署文档明确如何通过 HTTPS 反向代理仅暴露支付通知路径，使支付宝可达。通知入口接受支付宝验签，不要求用户 Cookie 或 CSRF；用户发起下单和查看本人的订单仍受现有会话、CSRF 和归属约束。应用私钥、支付宝验签公钥、商户身份和网关分环境管理；日志和订单列表不输出签名、私钥和完整支付通知。
- 支持待支付、已关闭、已支付、退款中、已退款和待人工处理状态；查单支持支付成功后关闭浏览器、通知丢失、重复投递。首版提供管理员对账与整单人工退款流程，退款使用唯一请求号和结果查询。同一事务撤回对应权益事件、重算其余已付款订单、保留已用记录和文档。退款影响后续升级/续期时先展示影响，由人工处理关联订单并留审计。不自动向用户扣款。沙箱和生产签约/凭据分别配置，验收时明确实测环境。
- 实施方接入前在支付宝开放平台核对当前电脑网站支付、异步通知、查单与退款契约及实际签约产品。官方入口：[电脑网站支付](https://opendocs.alipay.com/open/270/105899)。

## 6. 代码落点与交付顺序

1. **先做归属与账本。** 从 internal/state/permissions.go、internal/auth、docs/PERMISSIONS.md 核对旧角色、owner、共享授权，设计套餐目录、权益时段、订单、文件预占和按周期额度流水。提交幂等 schema 迁移，新增字段或接口保持现有契约。Redis 只可加速展示，所有额度判断、订单状态和发放依据来自 MySQL。
2. **再做统一额度入口。** 核查 internal/runtime/documents_batch.go、internal/state/document_batches.go、internal/ingest 及同步写入、CLI、MCP、REST 和恢复入口；同一条业务路径只占一次。对照 internal/modelapi/model_api.go 的 EmbedDocuments 与 EmbedQuery、internal/qdrant/store.go 的 ReembedInto 和 internal/kbconfig 的探测路径，显式传入计量目的、所有者和幂等上下文；避免在所有底层 HTTP 调用处无差别扣费。
3. **接入支付与 Console。** 新增本人套餐/用量、订单创建/查询、支付通知及管理员对账能力。账号菜单展示会员页、月/年切换、到期日、续费/升级报价、订单、字符总额/已用/预留和刷新日。库页区分自有/共享、库文件额度和操作者权限；批量上传显示每项拒绝原因。全链路使用中文，补 README 或 docs/USAGE.md、docs/PERMISSIONS.md 和支付部署说明。
4. **上线。** 先迁移和核对存量配额，再部署所有写入/计量入口，最后开放购买。准备暂停新下单的开关，暂停期间继续处理已付款通知、主动查单和已购买会员。生产商户签约、密钥与公网回调缺失时列为上线条件，不伪造付款验证。

| Free 库已有 9 份文档，REST 与 MCP 并发新增 | 至多受理一个新增名额；覆盖、取消、最终失败和重试后计数正确 |

| 旧 vip、无主库、已超限历史账号、系统重建、自付连接 | 权限兼容，后台用量可归因，历史数据可访问，商户额度与系统账隔离 |

按改动范围运行 Go 串行定向测试和前端相关测试。支付至少区分本地签名/幂等测试与支付宝沙箱真实联调。报告实际跑过的命令、验证结果和仍依赖商户提供的上线配置。
