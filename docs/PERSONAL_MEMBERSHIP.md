# 个人会员、支付宝与 Embedding 额度

本文描述 Praxis-RAG 首版个人会员的商品目录、知识库/文件配额、平台文档 Embedding 计量、有效期与升级规则，以及支付宝电脑网站支付的接入和上线检查。所有金额以人民币整数分保存；所有额度判断、订单状态和会员权益以 MySQL 为唯一事实来源，Redis 只可加速展示。

## 1. 套餐与价格

| 套餐 | 月卡 | 年卡 | 自有知识库 | 每库逻辑文件 | 每个会员月平台文档 Embedding 字符 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Free | 免费 | 免费 | 5 | 10 | 100,000 |
| Plus | ¥19.90 | ¥191.04 | 20 | 100 | 10,000,000 |
| Pro | ¥199.90 | ¥575.04 | 不限 | 不限 | 1,000,000,000 |

- Plus 年价 = 月价 × 12 × 0.8；Console 只对 Plus 展示“年付八折”。Pro 年卡按 ¥575.04 固定目录价，不按通用八折公式推算。
- 年卡分 12 个会员月发放额度。1B 表示每个会员月 10 亿输入字符；Pro 全年累计最多 120 亿。账本使用 `BIGINT`/Go `int64`。
- 额度没有现金价值、不结转、不自动扣费，首版不出售超额用量。
- 角色 `admin` / `vip` / `user` 保持不变。购买、续费、到期和退款只改会员权益，不改角色。

## 2. 归属与共享

- 知识库所有者为 `knowledge_bases.owner_user_id`。共享库不占共享者的自有名额；共享者与所有者共用该库所有者的文件上限和 Embedding 余额。
- 建库时只统计所有者名下知识库；管理员创建的历史无主库、系统模板仍走管理路径，不受个人套餐限制。
- 沿用全库/指定文件、`read`/`write` 授权。先校验操作者权限，再判断所有者权益。
- Free 可接受共享；Plus/Pro 可为**自己拥有**的知识库新建邀请。手工 `vip` 角色保留既有邀请权限，不会因购买或到期被改写。
- 会员到期后已有共享保留、可撤销，停止新发付费邀请。接受过期会员先前发出的未使用邀请时，服务端会重新校验邀请人的当前资格。
- 共享者能看到该库文件用量、上限以及“能否继续上传”和限制原因；详细 Embedding 余额和订单/账单仅所有者可见。

## 3. 文件额度

- 同一知识库中的一份逻辑文档计 1 个文件。分片、页面、解析图片、版本和自动重试不单独计数；覆盖原文档沿用原名额。
- 新文件在 `document_jobs` 受理事务中预占（active job 即预占），发布成功后成为实占，最终失败/取消后自动释放。删除已生效文档后释放；恢复需要重新取得名额。
- 建库在 MySQL 同一事务内锁定账号行、统计自有库并插入；文件受理同样在同一事务内统计“已发布文档 + 未结束任务”，因此并发提交至多一个越过剩余名额。批量上传按输入顺序逐项裁决，保证最后一个名额归属确定。
- 自动重试沿用 artifact 身份，不会重复预占。旧任务失败只释放自己的 active 行，不会释放后来者的占位。
- 会员到期后已发布文档、检索和下载继续可用；超限库只允许删除/覆盖，等用量降到上限以下才接受新文件。
- 历史迁移以现有已发布文档和未结束任务作为基线，重叠只计一次；超限存量保留，不删除。

## 4. 平台文档 Embedding 计量

### 4.1 单位与范围

- 计量单位是实际提交给文档 Embedding 的分片文本的 Unicode 码点数；空白和 overlap 重复字符计入。网页显示“字符”，不承诺等于模型 token 或 PDF 原文字数。
- 计入：平台提供的 Embedding 模型处理首次入库、内容变更、用户主动重新向量化（管理员触发的平台重建记系统账）。
- 不计入：相同内容跳过、查询 Embedding（基础检索成本，用完后旧文档仍可检索）、BM25、VLM、reranker、模型连通性探测。
- 解析前不按文件字节数预扣。

### 4.2 连接归属

- 知识库设置里的 `embedding_billing_source` 由管理员设置：`platform`（默认）或 `customer`。模板克隆会传递该来源。
- `customer` 表示该 Embedding 连接由客户自付，平台赠额不扣减；普通请求字段不能覆盖该标记。
- 现有模型连接默认按 `platform` 处理；有可靠依据的自付连接由管理员标记为 `customer`。

### 4.3 预留、结算与恢复

- 切分完成后、第一次付费 Embedding 调用前，按整份文档已知字符数原子预留。余额不足时不调用模型，任务失败类别为“所有者的文档向量化额度不足”，不会自动重试。
- 每个成功批次结算；未调用或明确失败批次的预留在最终失败/取消时释放。若 Embedding 成功但后续 Qdrant 发布失败，成功批次用量仍保留。
- 重新向量化按分段预留；余额不足时保留旧索引可检索，并报告已用额度。
- `embedding_usage.operation_id` 唯一：自动重试复用同一逻辑调用，最多向用户扣一次；不同用户主动发起的重算使用不同操作标识。
- 超时/进程崩溃等上游结果未知时保留 `pending_review`；后台维护在 24 小时后释放未核对预留，由平台承担不确定成本。重复回调或迟到结果不会追加扣款。
- 预留绑定原额度周期；跨月完成仍使用原周期，不吃新周期赠额。
- 账本只记录计数和标识（账号、周期、操作、文档版本、模型、批次身份、字符数），不记录正文、查询或模型密钥。

### 4.4 额度用尽

界面显示下次刷新时间。用户可以等待刷新、Free 升 Plus 或 Plus 升 Pro。Pro 仍有每月 Embedding 上限；“无限”只用于知识库数和文件数。续购同档只顺延现有到期时间，不会立即再发一份当前月额度。

## 5. 有效期、续费与升级

- 对外按 Asia/Shanghai 显示，内部存 UTC。周期左闭右开。月卡从开通时刻起一个日历月；年卡 12 个月，按原锚点逐月计算：1 月 31 日开通，2 月取 28/29 日，3 月恢复 31 日。
- Free 使用上海自然月。同一账号、来源和周期只发一次；Free→付费立即启用付费周期并停止使用旧 Free 余额；期满回到 Free 时复用本自然月 Free 账本。
- 同档可续月卡/年卡，顺延现有到期时间和额度周期。已过期重新购买从支付生效时刻起算。
- Plus→Pro 立即生效，原到期日不变；按原订单月卡/年卡的两档差价乘剩余服务时长占比，逐段计算后以分为单位最后四舍五入。当前月额度提高到 Pro 上限并保留已用量和预留；未来未开始时段一并按 Pro 覆盖。
- 首版不售付费期内降档；到期后可重新选择。
- 下单前展示服务端生成的应付金额、额度变化、生效和到期时间。升级报价绑定 `entitlement_version`；权益变化后旧报价不能再支付成功，冲突订单进入对账。
- 每个账号同时只允许一笔可支付的权益变更单；重复点击复用同一有效订单，意图不同则提示先处理旧单。

## 6. 支付宝支付与权益到账

- 首版使用支付宝电脑网站支付（`alipay.trade.page.pay`）。服务端商品目录生成商户订单号、金额和商品描述，前端只提交套餐、周期或升级意图。
- 订单快照保存价格、账号、套餐、周期规则和报价。浏览器回跳只展示订单状态；权益到账依据服务端验签的异步通知或主动查单。
- 通知校验：RSA2 验签、`app_id`、`seller_id`、`out_trade_no`、实付金额和交易成功状态。以支付宝交易号、商户订单号、权益事件唯一约束去重。
- MySQL 事务内确认付款并发放权益，提交后才向支付宝返回 `success`。禁止信任前端“支付成功”。
- 支持待支付、已关闭、已支付、退款中、已退款、待人工处理。关闭订单前先查支付宝状态；支付成功后关闭浏览器、通知丢失、重复通知和回调/查单并发都由主动查单和幂等事务兜底。
- 管理员可对账和整单退款。退款使用唯一请求号并查询结果；同一事务撤回对应权益事件、按剩余已付款订单重算会员快照，保留已用额度记录和文档。影响后续升级/续期时先展示影响，关联订单人工处理并留审计。
- 不自动向用户扣款。沙箱与生产使用不同 AppID、密钥、网关和回调地址。

## 7. HTTP 接口

所有接口返回 `{"detail": "..."}` 错误；会员/订单响应带 `Cache-Control: no-store`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/v1/membership` | 本人套餐、额度、目录和最近订单 |
| GET | `/v1/membership/orders` | 本人订单列表 |
| POST | `/v1/membership/orders` | `{"plan":"plus","period":"month"}` 或 `{"intent":"upgrade","plan":"pro"}` |
| GET | `/v1/membership/orders/{id}` | 本人订单；`?refresh=1` 主动查单 |
| POST | `/v1/membership/orders/{id}/close` | 关闭待支付订单 |
| GET | `/v1/workspaces/{namespace}/entitlements` | 当前库归属、文件额度、所有者可见的 Embedding 余额 |
| POST | `/v1/payments/alipay/notify` | 支付宝异步通知（无 Cookie/CSRF，RSA2 验签） |
| GET | `/v1/admin/billing/orders` | 管理员订单对账 |
| POST | `/v1/admin/billing/orders/{id}/query` | 管理员主动查单 |
| POST | `/v1/admin/billing/orders/{id}/refund` | 管理员整单退款 |
| POST | `/v1/admin/billing/orders/{id}/manual` | 标记人工处理并留备注 |

管理员接口还受现有本机直连/管理员会话限制；用户下单和查看本人订单受登录会话、CSRF 与归属校验约束。

## 8. 配置

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `RAG_MEMBERSHIP_PURCHASE_ENABLED` | `false` | 新下单开关；暂停时已付款通知、查单和会员权益继续处理 |
| `RAG_ALIPAY_ENV` | `production` | `sandbox` 或 `production` |
| `RAG_ALIPAY_APP_ID` | — | 开放平台应用 AppID |
| `RAG_ALIPAY_PRIVATE_KEY` | — | 应用私钥（PEM / base64 DER；单行可用 `\n`） |
| `RAG_ALIPAY_PUBLIC_KEY` | — | 支付宝公钥（不是应用公钥；支持证书） |
| `RAG_ALIPAY_SELLER_ID` | — | 收款方 PID；通知必须匹配 |
| `RAG_ALIPAY_NOTIFY_URL` | — | 公网 HTTPS 异步通知地址 |
| `RAG_ALIPAY_RETURN_URL` | — | 浏览器回跳地址，建议 `/console#/membership` |
| `RAG_ALIPAY_GATEWAY` | 按环境 | 覆盖网关 |
| `RAG_ALIPAY_TIMEOUT_MINUTES` | `30` | 订单支付窗口（1..21600 分钟） |

## 9. 部署与上线检查

1. 先迁移并核对存量配额：为新表建表、补齐 Free 会员行、检查 `knowledge_bases.owner_user_id`、已发布文档和未结束任务；超限存量保留。
2. 部署所有写入/计量入口后再开放购买：`rag-service`、`rag-document-worker`、CLI/MCP 写入路径必须使用同一套 state/membership 代码。
3. 在支付宝开放平台确认已签约“电脑网站支付”，核对当前下单、异步通知、查单、关闭和退款契约；沙箱验收和生产签约分别配置。
4. 生产需要公网 HTTPS 回调。反向代理只暴露 `POST /v1/payments/alipay/notify`，不要暴露服务默认 loopback 管理面。通知入口不需要用户 Cookie/CSRF；其他会员接口仍需登录。
5. 应用私钥、支付宝公钥、AppID、SellerID 和网关分环境管理；日志、订单列表和页面不得输出签名、私钥或完整通知。
6. 缺少生产商户签约、密钥或公网回调时，保持 `RAG_MEMBERSHIP_PURCHASE_ENABLED=false`。系统不会伪造支付验证，也不会给未验签回调发权益。

## 10. 已知限制

- 首版只服务 Web Console；不提供移动端 SDK、自动续费/免密支付、超额用量购买或付费期内降档。
- 支付宝退款结果不确定时订单保持“退款中”，由管理员按唯一退款请求号重试或查单，不自动向用户扣款。
- 会员额度账本中的“字符”与模型 token 不是同一单位，页面不承诺二者换算。
- 手工 `vip` 角色的历史邀请权限保留，但不会因此获得付费套餐或永久平台 Embedding 额度。
