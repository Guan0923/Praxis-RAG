# Praxis RAG PDF 修复与验证记录

日期：2026-09-09。分支：`codex/pdf-parsing-fidelity`，基于本地 `main` 的 `f6e8515`。

## 结论

已修复项目接入过程中丢失顺序、注解、表格列与公式的处理逻辑。不能宣称四项识别能力全部达标：CodeFormulaV2 的复杂公式识别、Docling 的部分图注关联和扫描 OCR 仍有真实失败样例，见下文。用户后续提供的论文尚未加入验证。

修改位于隔离工作树，没有提交、合并、推送或重启现有服务。测试使用独立数据目录、独立 HTTP 端口和本地 Qdrant，没有重建现有知识库。

## 已实现

- 本地 Docling 2.126.0 + CodeFormulaV2，固定已有模型版本；修正生成缓存，使用 3 倍紧裁剪、单公式推理。空输出、超时、截断和解析失败会报错，不关闭公式功能后假装成功。
- 保存原生 JSON、统一内容列表、正文、图像裁剪和 OCR 记录。沿用 Docling 阅读顺序；保留原始引用、编号、页码与所有位置，不对 LaTeX 做数学改写。
- 原始图注、表题、脚注分开保存。短注解不删除，未关联注解保留原位并标记；视觉模型描述仅用于检索，不冒充原文。
- 表格保留空列、行列数、合并范围、多层表头。各行入库时携带完整表头。正文使用用户选择的切分参数；公式和表格行不可从中间截断，超过模型输入上限明确失败。
- 上传、CLI PDF 导入和 MCP 全文读取共享解析链路；MCP 分页不切断公式。去重包含解析版本；旧 PDF 需要显式重新导入。
- 文件、图表资源、索引及文档清单在发生可捕获错误时回滚。测试覆盖磁盘写入失败和资源安装失败；这不是断电、进程强杀或多进程环境下的事务保证。
- OCR 不再丢弃低于默认置信度的文字，记录原始置信度并将页面警告带入检索结果。保留文字不代表文字正确。

## 测试范围

常规测试：`115 passed, 3 skipped`，另有 4 条原有 MCP 旧订阅接口弃用提示。跳过项为需要单独启用的浏览器、旧真实模型验收及新 PDF GPU 验收；新 PDF 验收已单独执行。Ruff 检查通过。

测试覆盖短图注、未关联注解、正文与图表顺序、公式边界、空列、合并单元格、多层表头、跨页来源、五种切分策略、输入上限、重复检测、文件和 Qdrant 失败恢复。部分错误通过受控故障注入复现，不代表真实模型准确率。

真实验证使用 RTX 3060 12GB、已有 Docling 2.126.0 环境、本地 CodeFormulaV2 / EasyOCR / TableFormer / Granite Vision / BGE-M3。启用离线模式，没有云端推理或共享环境升级。

HTTP 验证通过独立真实服务执行：上传 PDF、重复检测、混合检索、官方 MCP 客户端逐页读取。直接比较原生结构、保存正文与 Qdrant 内容，核对顺序、全部公式 LaTeX、图表数据及来源关联。检索检查要求实际找回对应公式和原图注，不仅检查结果非空。MCP 分页拼接结果必须与保存正文完全一致。

CLI 另用隔离目录的 `aviation.pdf` 真实导入：`discovered=1 imported=1 chunks=11 failed=0`。CLI 使用默认切分参数，HTTP 验收使用 recursive / 256 / 32，块数不同属于预期。
